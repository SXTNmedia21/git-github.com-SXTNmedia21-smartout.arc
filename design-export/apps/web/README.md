## 1. Entry point & how to run
**Open `apps/web/Smartout Web Version 1.html`.** (This is the ONLY entry file — a previous duplicate `Smartout.html` was removed. Don't recreate it.) It is the living app, not a frozen version; all work continues inside it.

It loads, in order (paths relative to `apps/web/`):
1. Google Fonts (Instrument Serif, Geist, Geist Mono)
2. `shared/styles.css` — **Nordic Split design system** (tokens + components). **Never duplicate/fork.**
3. `shared/shell.css` — app frame (topbar, sidebar, command palette, chat, Botsson, doc-mode, account pages, toasts)
4. `shared/pages.css` — shared page primitives (`so-*` panels); per-page styles live next to each page in `pages/*.css`
5. `shared/data.js` — shared mock data → `window.SmartoutData` (USERS, TASKS, FOLDERS, MANUALS…)
5b. `shared/handbook-data.js` (+ the other `shared/*-data.js`) — extend `window.SmartoutData` with domain data (HANDBOOKS, HB_HEALTH, ansatte/hms/lonn/recon/kommunikasjon… plain scripts — load before the babel files)
6. `shared/shell.jsx` — everything below registers globally; exposes `window.Ic`, `window.useToast`, `window.CreateButton`, `window.SO_PAGES`, `window.__SmartoutBoot`
7. `pages/*.jsx` — one file per route, each registers into `window.SO_PAGES`
7b. `pages/handbook-shared.jsx` → `pages/handbook-views.jsx` → `pages/handbook-editor.jsx` → `pages/handbook-create.jsx` → `pages/handbook.jsx` — the **Bibliotek / håndbok system** that takes over Dokumentmodus. Load IN THAT ORDER (shared primitives first); exposes `window.Hb*` components + `window.HandbookApp`. Styles in `pages/handbook.css`.
8. boot script calls `window.__SmartoutBoot()` (renders `<App/>` after all pages registered)

**Folder layout:** `apps/web/shared/` (design system + shell + all data), `apps/web/pages/` (one `*.jsx` per route + its `*.css`, plus the `handbook-*.jsx` module), `apps/web/docs/` (living Design System doc). The app is self-contained — it no longer reaches outside `apps/web/`. (Sibling `apps/mobile/` is a placeholder for the future mobile client.)

**To add a page file, add its `<script type="text/babel" src="pages/x.jsx">` line BEFORE the boot script.**

## 2. New-agent orientation (5-minute map)
- The **shell** (chrome + state + routing) lives entirely in `shared/shell.jsx`. ~1100 lines, sectioned with `// ---------- name ----------` banners.
- The shell renders `<TopBar>`, `<Side>` (or `<DocSide>` in doc-mode), the active page (or `ProfilePage`/`SettingsPage`/`AccessDenied`), plus overlays: `<BotssonChat>`, `<ChatPanel>`, `<CommandPalette>`.
- **Pages** are independent: each `pages/*.jsx` is an IIFE that defines a component and registers it via `window.SO_PAGES = Object.assign(window.SO_PAGES||{}, { route: Component })`.
- Most admin routes are real pages now (see §8). Unbuilt routes render `StubPage` (a clean skeleton placeholder) until built.
- State (route, mode, role, theme, collapsed, season) persists in `localStorage` key **`so_app`**.

## 4. Modes & access control (role-based)
Two modes, switched by the **Adminmodus** toggle (sidebar footer):
- **Privat (off)** — employee «Min side»: `min-dag` + a **Min side** nav group (`mine-vakter`, `min-lonn`, `min-laering`, `mine-kontrakter`, `mitt-cv`). Demo persona for the self-service pages: **Jonas H. (Sous-chef · Kjøkken)**.
- **Admin (on)** — Workforce Management: full grouped nav (Drift / Team / Økonomi), home = `oversikt`.

**Gated, not just hidden:** `CURRENT_USER.canAdmin` decides if Admin mode exists (toggle only renders when true). A guard in `App` re-validates every change — a non-admin can never enter admin mode (even via tampered `localStorage`); any route outside the active mode's set redirects to that mode's home; disallowed renders hit `AccessDenied`. Profile menu has **Vis som leder / Vis som ansatt** to demo the gate. When you add an admin page, the guard covers it automatically (it's in `ADMIN_NAV`).

> Mr. Botsson's profile/permission-management admin page is intentionally NOT built here — it comes from another project.

## 5. Conventions
- **Add a page:** create `pages/<route>.jsx` as an IIFE; component returns `<main className="sk-main"><div className="sk-wrap">…</div></main>` (standard) or `.sk-main.full` (full-bleed grid/calendar). Register via `window.SO_PAGES`. Add the `<script>` tag before the boot script. To appear in nav, add an entry to `ADMIN_NAV` or `PRIVATE_NAV` in `shared/shell.jsx`.
- **Styling:** shared panel primitives are `so-panel`, `so-panel-head`, `so-grid-2`, `so-stack`, `so-av`, `so-empty` in `shared/pages.css` — reuse them. Page-specific rules go in that page's own `pages/<name>.css` (prefixed `.dash-…`, `.opp-…`) and get a `<link>` in the entry HTML. Component-level styles live in `shared/styles.css`; never duplicate.
- **Icons:** `<Ic n="name" s={size} c={color} sw={stroke} />`. Add glyphs to the `ICONS` map at the top of `shared/shell.jsx`. Lucide-style strokes only.
- **Toasts/undo:** `const toast = useToast(); toast("Lagret", { undo: () => … })`.
- **Numbers/time/IDs** use `var(--font-mono)` (Geist Mono).
