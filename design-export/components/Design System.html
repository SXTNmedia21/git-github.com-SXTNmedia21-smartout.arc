Design System
web & app

Ett delt referansepunkt for design og utvikling av Smartout — på tvers av web (driftsleder-cockpit) og app (frontline mobil). Begge flatene bygger på samme tokens, type og farger fra én rot — styles.css. Dette dokumentet speiler produktet slik det faktisk er bygget, og dokumenterer de delte komponentene — Veiledning (Flow Player), Opprett oppgave og Opprett vakt — side om side, slik at web og app holder samme stil.

Arkitektur

To flater, ett system

Web og app er ikke to designsystemer — de er to komponentlag over samme rot. styles.css definerer alle tokens (farge, type, rom, radius, skygge, mørk modus). Web legger sine klasser oppå (sk-*, so-* + sidespesifikke), appen sine (m-*). Endrer du en token, endrer begge flatene seg.

Web — driftsleder-cockpit

Tett informasjon, mus + tastatur, mange ruter og overlays. Desktop-first, responsiv. Klasser: sk-* (skall), so-* (delte side-primitiver), og sidelag i pages/*.css. Overlays = sentrerte modaler / sidedrawere.

App — frontline mobil

Handlingsfokus, én hånd, telefonbredde (≤ 430px). Mobile-first, rå canvas uten bezel. Alt prefikset m-* i mobile.css. Overlays = bunnark (bottom sheets) og helskjerm-takeovers.

Primitiv-kart — web ↔ app

Samme rolle, plattformtilpasset klasse. Bygger du den ene, finn motparten her i stedet for å lage en ny.

Web = sentrert modal med fremdriftslinje; app = helskjerm med steg-prikker. Begge: oransje aksent, serif-titler, navnet «Veiledning».

3 · Vaktkontroll (Shift Controller)

Vakter styres ikke fra en isolert «Ny vakt»-boks — de håndteres i Shift Controller på vaktplanen (vaktplan-controller.jsx). Du plukker en vakt i rutenettet og åpner kontrolleren: et faner-cockpit for én vakt med Rolle / Team / Sone, Funksjoner & kompetanse (skjenkebevilling, vaktansvarlig), avvik/issues, koblede oppgaver (TaskDrawer) og Lønnsgrunnlag. 4 · Flow Controller (Compliance Flow)

Flow Controller er HMS/compliance-verktøyet — den faktiske OppFormViewer (web) og MFormViewer (app). Du scroller ovenfra og ned gjennom seksjoner med kontroller og innskutte huskeregler, og signerer til slutt (genererer bevis til loggen). Kontrolltyper: Måling · Spørsmål (ja/avvik) · Vurdering · Foto · QR · Signatur. Begge flater leser ett delt skjema — SmartoutData.resolveControlForm(task) i shared/data.js — så de kan aldri komme ut av synk.

Gjenbrukbar på tvers av kontrolldomener: samme komponent driver Vernerunde (vern), HMS, IK / Mat (egenkontroll) og innhenting (mottakskontroll). En oppgave løses opp til riktig skjema etter domenet sitt — CONTROL_FORMS[id] ellers et CONTROL_TEMPLATES[domene].

Arkitektur-kobling

UI ↔ Core Structure

Designsystemet er ikke bare visuelt — det hviler på datamodellen i Core Structure (D1). Et delt vokabular (ADR-0429) holder UI, AI, docs og database i takt på tvers av web og app. Ordet «rolle» er bevisst ikke et Smartout-begrep — det blandet sammen stilling og tilgangsnivå.

Tilgangsnivå styrer modus — på begge flater

Web har to moduser via Adminmodus-toggelen: Privat (ansatt) og Admin (Workforce Management). App speiler dette med Ansatt ⟷ Leder fra Mer-skjermen. Begge styres av samme profile.role / canAdmin. På web er det rolle-styrt med rute-vakt; på app adapterer de fem fanene innhold til modus.
