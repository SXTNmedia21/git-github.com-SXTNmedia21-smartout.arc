# Approved journey folder — 13-file reference

Generated by `ops/04-approve.md`. Mirrors `docs/engines/system-intelligence/05-protocol-pipeline.md` §4 + `07-journey-package-compiler.md`.

```
docs/journeys/<slug>/
├── journey.md              # SOURCE OF TRUTH (frontmatter + step body)
├── ROADMAP.md              # the button (entry-point UX)
├── MISSION.md              # the agent trigger (paired with ROADMAP)
├── LIVE-EXPERIENCE.md      # prose flow as user lives it
├── LICENSE.md              # authority + policy contract (C4 manifest)
├── FLOW.md                 # ★ chronological function list — closed-loop spine
├── API.md                  # merged: endpoints + events + functions
├── DATAFLOW.md             # tables touched, data shapes, side-effects
├── COUPLINGS.md            # journeys/missions/services this binds to
├── e2e.spec.ts             # Playwright — generated from FLOW.md
├── RESCUE-PROMPT.md        # agent context for stuck/failed runs (optional)
└── ir/
    ├── journey.yaml        # canonical immutable IR (post-approve)
    └── journey.hash        # sha256 of journey.yaml
```

## Pairing rules (enforced at approve)

- `ROADMAP.fires_mission == MISSION.mission_id`
- `MISSION.roadmap_id == ROADMAP.roadmap_id`
- `MISSION.stages` reference real `journey.md` step keys
- `LICENSE.capabilities` ⊆ {`run_dev`, `run_guided`, `publish_mission`, `publish_guide`}
- `FLOW.md` rows with `trigger_ref != null` cover every `journey.md` step (exact set match)
- `e2e.spec.ts` = pure function output of FLOW.md (no hand-edits visible at next regen)

## Why dropped (from earlier 19-file proposal)

- User Test, Knowledge Test, Function Test → **dropped**. They're observability reports (read from `journey_event` + `journey_run` + `journey_step_log`), not authored artefacts.
- Inference-pattern, State-card → **moved into `ir/`** (runtime-only, not authoring outputs).

13 files. Each maps to a distinct consumer surface.
