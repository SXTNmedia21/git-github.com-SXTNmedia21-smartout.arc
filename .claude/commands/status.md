# Status

Regenerate the development dashboard from live git state and display it.
Updated 2026-04-20: tracks campaigns and sub-sorties alongside sorties.

## Contract

`DASHBOARD.md` is a DERIVED view of `git worktree list` + filesystem scan.
Never hand-edit its tables. This command is the only official way to
refresh them.

Three classes of worktree are tracked separately:

- **Sortie** — short-lived, named `~/dev/<repo>-wt-N`, branch `feat/<name>`. Goes into "Active Worktrees".
- **Campaign** — long-lived, named `~/dev/<repo>-<campaign>`, branch `campaign/<campaign>`. Goes into "Active Campaigns" with staleness (commits behind development, last sync).
- **Sub-sortie** — short-lived child of a campaign, named `~/dev/<repo>-<campaign>-wt-N`, branch `feat/<campaign>-<name>`. Goes into "Active Sub-Sorties" grouped by parent campaign.

## Steps

### Step 1: Inventory the live state

Gather authoritative facts. Classify each worktree as sortie, campaign,
or sub-sortie by branch prefix and path shape.

```bash
# Resolve current repo root — /status operates on whichever repo you're in
REPO_ROOT="$(git rev-parse --show-toplevel 2>/dev/null)"
if [ -z "$REPO_ROOT" ]; then
  echo "error: /status must be run from inside a git repo"; exit 1
fi
REPO_NAME="$(basename "$REPO_ROOT")"
REPO_REMOTE="$(git -C "$REPO_ROOT" config --get remote.origin.url 2>/dev/null || echo 'no-remote')"

# Worktrees (authoritative — git's own view, scoped to THIS repo)
git -C "$REPO_ROOT" worktree list

# Scan candidate directories:
#   ~/dev/<repo>-wt-N          → sortie
#   ~/dev/<repo>-<camp>        → campaign           (branch campaign/*)
#   ~/dev/<repo>-<camp>-wt-N   → sub-sortie of camp (branch feat/<camp>-*)
# Also include legacy ~/dev/wt-N.
for d in ~/dev/wt-* ~/dev/"$REPO_NAME"-*; do
  [ -d "$d" ] || continue
  WT_REMOTE="$(git -C "$d" config --get remote.origin.url 2>/dev/null)"
  [ "$WT_REMOTE" = "$REPO_REMOTE" ] || continue

  branch="$(git -C "$d" branch --show-current 2>/dev/null)"
  basename_d="$(basename "$d")"

  # Classify.
  if [[ "$branch" == campaign/* ]]; then
    kind="campaign"
    campaign="${branch#campaign/}"
    # Staleness: commits behind origin/development, last sync commit date.
    git -C "$d" fetch origin development 2>/dev/null || true
    behind=$(git -C "$d" rev-list --count HEAD..origin/development 2>/dev/null || echo "?")
    ahead=$(git -C "$d" rev-list --count origin/development..HEAD 2>/dev/null || echo "?")
    last_sync=$(git -C "$d" log --grep="^sync($campaign)" -1 --format='%ar' 2>/dev/null || echo "never")
  elif [[ "$basename_d" =~ ^${REPO_NAME}-(.+)-wt-[0-9]+$ ]] && [ -d ~/dev/"${REPO_NAME}-${BASH_REMATCH[1]}" ]; then
    kind="sub-sortie"
    campaign="${BASH_REMATCH[1]}"
  else
    kind="sortie"
    campaign=""
  fi

  echo "${basename_d} [${kind}${campaign:+ of $campaign}]: $branch"
  echo "  last commit: $(git -C "$d" log -1 --format='%ar — %s' 2>/dev/null)"
  echo "  dirty files: $(git -C "$d" status --porcelain 2>/dev/null | wc -l)"
  if [ "$kind" = "campaign" ]; then
    echo "  vs development: ${behind} behind, ${ahead} ahead, last sync ${last_sync}"
  fi
done

# Pending journey files (derived — match JOURNEY files against active branches)
ls "$REPO_ROOT"/docs/journeys/JOURNEY-*.md 2>/dev/null

# tmux context (informational)
tmux list-sessions 2>/dev/null || true
```

### Step 2: Regenerate DASHBOARD.md

**Overwrite** `$REPO_ROOT/docs/DASHBOARD.md` completely (i.e. the DASHBOARD
for whichever repo you're currently in). Do NOT edit existing rows — rebuild
from scratch. This is the whole point of /status.

If the repo's DASHBOARD.md contains project-specific sections beyond pure git
state (e.g. infra tables, council, ADR registry), **preserve them** — only
rebuild the worktree/journey sections. When in doubt, report to the user
instead of overwriting.

Template:

```markdown
---
title: Development Dashboard
status: live
updated: {today ISO date}
module: meta
tags: [dashboard, worktrees, campaigns, git-state]
---
```

### Step 3: Display to user

Show the rebuilt DASHBOARD contents, then report what changed:

```
Dashboard regenerated from git worktree list.

Active: {count} worktrees
Free:   {count} slots
Pending journeys: {count} missing

Changes since last /status:
- wt-N: {added | removed | branch changed}
- ...

Stale warnings:
- wt-N: last commit {N days ago} — consider /end-session or /close-feature
- wt-N: {N dirty files} — uncommitted work
```

### Step 4: Flag anomalies

Report if you see:

- A worktree directory that's not in `git worktree list` (orphan)
- A `feat/*` branch with no worktree (parked branch)
- Uncommitted changes older than 3 days
- Two worktrees on the same branch (should never happen)

Do NOT fix these automatically. Report and let the user decide.

## Important Rules

- ALWAYS overwrite DASHBOARD.md completely — never edit rows in place
- NEVER add "Session History" or "Recent Closures" sections — those belong in `~/dev/second-brain-v2/ops/activity-log.md` per ADR-0075
- NEVER write to `docs/SESSION.md` — the file is deleted per ADR-0075
- If `git worktree list` is empty or errors, report it and do NOT clear DASHBOARD — that would lose information
