## T1 — Migrate 10 capability `engine_event` bypass sites to `emit()`

**Title:** `fix(ai): migrate 10 capability engine_event bypass sites to emit() registry`
**Priority:** Medium
**Labels:** `Path → packages/ai/capabilities`, `Operation → refactor`, `Stack → TypeScript`
**Related:** ADR-0156, L-0064
**Estimate:** 2–3 dev-days (split into 3 sub-PRs per Supervisor)

### Context

Post-impl R1 (2026-04-19) fixed `operations.complete_task` bypass but Layer 4 trace flagged 9 OTHER bypass sites across 7 files in the same pattern: `supabase.from("engine_event").insert({ event_type, payload })` — direct insert skipping `emit()` registry, therefore no PostHog / logger / activity_trail fan-out.

Agent Coord further verified: event name format divergence — bypass sites use DOT separator (`"deviation.reported"`, `"ops.triage.classified"`) while the registry uses SPACE separator (`"session pending_signoff"`, `"session_task completed"`). `toDotNotation` only converts single spaces to dots — cannot produce 3-segment names.

| 5 | `packages/ai/src/capabilities/operations-intelligence/tools.ts:72` | `ops.triage.classified` | `ops_triage classified` | `ops_triage.classified` |

### Pre-flight — duplicate-emit audit (Agent Coord Trust Gate condition)

Before any PR: grep `emit({ event: "channel_message sent"` + `"day_brief compiled"` etc. across apps/web + packages/ai + services to verify these event names aren't ALREADY emitted by a Server Action or dispatcher listener. If yes → migration would produce duplicate activity_trail rows. Document findings in PR description.

### Scope (split into 3 sub-PRs per Supervisor)

- **PR 1 — communication capability** (sites 1–3): `channel_message.ts`, `compile-day-brief.ts`, `compile-preclose.ts`
- **PR 2 — operations-intelligence capability** (sites 5–10, 6 sites): `tools.ts`, `monitor-tools.ts`, `predict-tools.ts`, `learn-tools.ts`
- **PR 3 — operations deviation.reported** (site 4): `operations/tools.ts:214`

Each PR adds registry entries + routing destinations + call-site refactor + E2E verification.

### Special case — operations-intelligence/tools.ts:65

Takes `event_type` as a Zod-validated PARAMETER (caller-supplied string). Cannot be statically registered. Either (a) add an allow-list enum to Zod, or (b) build runtime registry lookup. Design decision — flag in PR 2 description.

### Acceptance

- [ ] Duplicate-emit audit documented
- [ ] All 10 sites routed through `emit()` with registry event types
- [ ] Registry entries added with `entity: EntityRef` where applicable (per L-0064 / post-impl R1 B4 precedent)
- [ ] Typecheck + E2E pass
- [ ] Old `engine_event.insert()` calls deleted

## T3 — Wire `hasMinimumRole` callers through `gate_action()`

**Title:** `refactor(engine): wire hasMinimumRole Server Action callers through gate_action()`
**Priority:** Medium-High
**Labels:** `Path → dashboard/_actions`, `Path → engine_authority_config`, `Operation → refactor`, `Stack → TypeScript`, `Stack → Supabase`
**Related:** ADR-0156 follow-up, L-0065
**Estimate:** 0.5–1 dev-day (code-only; schema already exists)

### Context

**Correction from post-impl R1 — ADR-0156 deferral was based on stale info.** The `engine_authority_config.min_role` column was added 2026-04-10 via `supabase/migrations/20260410000001_add_min_role_to_authority_config.sql`. The `gate_action()` function exists and consumes `min_role` via `_role_rank()` comparator (`supabase/migrations/20260509100000_gate_action_four_eyes_history.sql`). Fact-check captured as L-0065.

Current hardcoded `hasMinimumRole()` in `apps/web/src/app/dashboard/_actions/_shared.ts:43-59` uses inline role rank. Callers: `signoff-session-action.ts:51,123` + `send-broadcast-action.ts:47`. Plus `toggle-session-task-action.ts` will need role gating too (currently no role check — intentional for employee self-toggle, but worth review).

### Work

1. **Refactor** `_shared.ts:hasMinimumRole()` to call `gate_action()` RPC and return the `allow`/`downgrade_to` result.
2. **Seed** `engine_authority_config` rows for: `session.signoff` (`min_role=manager`), `broadcast.send` (`min_role=manager`), `session.close` (`min_role=admin`). Use existing seed migration pattern (see `supabase/migrations/20260417170000_billing_query_authority_seed.sql` for reference).
3. **Migrate** 3 Server Action call sites to use the registry-driven gate.
4. **Delete** inline role rank from `_shared.ts` once callers migrate (keep `resolveCurrentProfile()` — that's orthogonal).
5. **Document** C4 invariant: `min_role` = identity restriction (WHO), orthogonal to channel restrictions (HOW/WHERE) from ADR-0078.

### Optional fine-grain (Agent Coord)

Current `engine_authority_config` is per-workspace-per-capability. If capability-grain rows over-restrict at tool level, add optional nullable `tool_name` column so one capability can have different min_role per tool. Defer unless first migration reveals the need.

### Acceptance

- [ ] `gate_action()` wired into `_shared.ts:hasMinimumRole()` or its replacement
- [ ] Seeds for `session.signoff`, `broadcast.send`, `session.close` in engine_authority_config
- [ ] 3 Server Action callers migrated
- [ ] No inline role rank remains
- [ ] E2E: manager can signoff-pending; employee cannot send broadcast
- [ ] HANDOFF-overview-v2.md deferral note removed
