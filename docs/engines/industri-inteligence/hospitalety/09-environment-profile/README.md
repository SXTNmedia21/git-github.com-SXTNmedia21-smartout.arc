# Environment Profile

## Purpose

Capture the operational environment assumptions that affect behavior, risk, and testing.

Keep it minimal and practical.

## Minimal Structure

- Service context (pace and workload pattern)
- Workforce context (language, literacy, turnover)
- Compliance context (critical controls)
- Physical context (zones, handoff points, risk areas)
- Technical context (mobile-first or desktop-heavy usage)

## Why this matters

The same journey can behave very differently across environments.
Environment profile prevents false assumptions and helps tune templates and tests.
