## Fix details

### Fix 1 — systemPromptSlices injection

File: `services/stage-engine/src/core/agent-router.ts`

`bundle.systemPromptSlices: string[]` was generated by `factory.ts:59`, preserved through `authority.ts:152` and `chat-tool-resolver.ts:251`, then dropped at the prompt-assembly site. Now appended to `finalSystemPrompt` AFTER worldState/ctx blocks (slices last = LLM weights highly).

Behavior change: when `HARNESS_ADAPTER_CHAT=true`, LLM receives per-page system context alongside tool definitions.

### Fix 2 — authority audit telemetry

Files: `packages/telemetry/src/registry.ts` + `services/stage-engine/src/core/agent-router.ts` + `services/stage-engine/src/core/session-recorder.ts`

Added new telemetry event `botsson.authority_filtered`. Payload: `{ workspace_id, actor_id, channel, blocked_count, blocked_tools[], blocked_rules[] }`. Emitted from agent-router after authority unpack when `bundle.authority.blockedTools.length > 0`.

Deviations from audit-recommended fix:
- `denied_reasons` → `blocked_rules` — the `BlockedToolEntry` type has `rule: AuthorityRuleName`, not `reason: string`
- Added `"authority_filtered"` to `TurnPhase` closed string union for recorder.recordTurn integration
- Used fire-and-forget `void emit().catch(...)` not `await` — matches existing agent-router recorder pattern

### Fix 3 — docstring correction

File: `services/stage-engine/src/core/chat-tool-resolver.ts`

Phase 3 docstring at line 165-188 claimed "client-tool-wins on modelToolName collision" for mission-vs-page-tool merge. Verified: chat path NEVER imports `getMission` or `MISSIONS` from `@smartout/ai/missions`. The claim was hollow — no collision could exist because no mission tools enter the merge. Rewrote docstring to describe actual behavior: merge is between capability-classifier tools + client-shipped page tools. No mission contribution.

Decision: chat IS mission-agnostic by current architecture. Mission-driven prompts come via `fetchActiveStateSummary` (DB roadmap), not MISSIONS registry. Wiring mission tools would be scope expansion — separate sortie if needed.

## Learnings

| L | Discovery |
|---|---|
| **L-0271** | 5 sorties of ADR-0327 (Phase 1+2 / 3 / 3.5 / 4 / E2E) shipped with green unit + integration tests + Playwright spec — and STILL had 2 🔴 silent bugs. Phases pass tests because they test their slice. `bundle.systemPromptSlices` was correctly generated AND correctly preserved through layers AND correctly returned in bundle — but DROPPED at the sink. No unit test asserts the sink reads it. Lesson: end-to-end audit by independent agent (different head, different lens) AFTER ship is the only way to catch this class. Schedule audit BEFORE flag-flip, not after merge. |
| **L-0272** | Audit-recommended fix shapes often don't match codebase types verbatim. Audit said `denied_reasons` — real type is `rule: AuthorityRuleName`. Trust types over audit phrasing. |
| **L-0273** | `TurnPhase` closed string union in `session-recorder.ts` requires explicit type extension for new recorder phases. Adjacent-file change required when adding telemetry recorder integration. |

## Known issues / debt

- Mission integration for chat path remains unwired. If/when mission-driven chat sessions need their own toolsets, separate ADR + sortie required. Current behavior: chat ignores missions entirely.
- The `botsson.authority_filtered` event registry entry uses a forward-compatible payload shape — `blocked_rules` is array even when one rule blocked one tool. PostHog query patterns should accommodate.
- Voice path authority logging stays observational (console only, `agent.ts:281`). If prod-grade voice audit required, separate sortie.
