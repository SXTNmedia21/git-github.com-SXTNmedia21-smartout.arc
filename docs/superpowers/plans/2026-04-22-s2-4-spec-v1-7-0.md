### Stale-path grep gate (MERGE BLOCKER)

Per Gate B code-reviewer: v1.6.0 contains 6 confirmed references to `packages/ai/src/journey/*` at lines 229, 232, 233, 237, 307, 912. Every such reference must become `packages/journey-ir/src/*` in v1.7.0. Exit gate:

### AuthorityLevel prose verification (CVE-adjacent)

Per Gate B code-reviewer risk #10: any prose about `AuthorityLevel` defaults MUST be verified against `supabase/migrations/20260516000400_journey_authority_seed.sql`, NOT against v1.6.0. The seed migration is the source of truth.

Required verbatim statement near the authority discussion:
> "Capability authority levels are explicit per-capability rows in `engine_authority_config` (seeded via `20260516000400_journey_authority_seed.sql` per ADR-0176). Per ADR-0173: `journey.run_dev` / `publish_mission` / `publish_guide` = `suggest`+`admin`; `journey.run_guided` = `autonomous`+`employee`. There is no default authority — default-allow via `gate_action` RPC + missing row is a CVE-class trap (L-0066, L-0097). The `AuthorityLevel` type at `packages/ai/src/capabilities/types.ts` is a Node-side advisory for the tool-selector and router; the DB RPC enforces only `min_role` downgrade and `requires_four_eyes`, not level semantics. See ADR-0175 clarification row in the decision log."

### Enum reference consistency

Every v1.7.0 reference to a journey status column MUST use `journey_version_status`, NOT `journey_status`. v1.6.0 at line 816 uses "ALTER TYPE journey_status ADD VALUE" — that pattern is banned (ADR-0172 hard prohibition). Replace all `journey_status`-as-version-state references with `journey_version_status`.

Exit gate:
```
grep -n "journey_status" docs/superpowers/specs/2026-04-22-journey-runner-suite-mental-model.md
```

Any match must be a reference to the runtime execution enum (`journey_status` in `journey` table for live runs), NOT a version-authoring state. If ambiguous, replace with `journey_version_status`.

### Phantom contract check

Every journey event name in v1.7.0 must map to a registry entry. Verify:

## Artefact 2 — ADR-0174 delta appendix structure

Append to `docs/decisions/0174-adr-0074-journey-ir-unification-completion.md`:

### `## Delta Spec: adapter contract + cutover + deletion window`

Required subsections:

#### A. Adapter contract — `protocolToJourneyIR()`

```typescript
// Lives in: packages/journey-ir/src/adapter/protocol.ts (M3)
export function protocolToJourneyIR(
  protocol: ProtocolDefinition
): JourneyIR;
```

Required input fields (from existing `ProtocolDefinition`), required output fields (from JourneyIR type family — to be defined in M3). Pure function; no DB access; no emit. Document rollback: if `protocolToJourneyIR(p)` throws for any existing protocol, adapter is incomplete.

#### B. Cutover sequence (3 steps, sequential)

1. **Dual-write** (M3 early): Mission + Docs + Audit generators read `ProtocolDefinition`, call adapter, consume JourneyIR. Legacy protocol paths still present in `apps/e2e/generators/`.
2. **Flip** (M3 mid): Generators read JourneyIR directly; adapter still exists but unused. Legacy `docs/protocol/` reads removed.
3. **Delete** (M3 end): Adapter file deleted. `ProtocolDefinition` type deprecated, kept only for backwards compat on the one-shot migration of 68 existing records. After that migration, the type itself is deleted.

#### C. Deletion window

Adapter deletion requires: (a) zero imports from `packages/journey-ir/src/adapter/protocol.ts` outside tests, (b) zero reads of `docs/protocol/` from `apps/e2e/generators/*`, (c) source-of-truth migration #6 complete. All three are checked via CI grep gates at the "Delete" step PR.
